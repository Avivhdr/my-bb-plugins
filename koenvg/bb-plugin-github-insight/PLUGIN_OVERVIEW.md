See the checks of a thread's pull request, and the pull requests that wait for your review, without leaving bb.

- A **PR** tab in the thread's right panel, with an **Overview** sub-tab (status and conversation) and a **Files** sub-tab (diff and review threads).
- The Overview conversation shows PR comments, reviews, commits, and ready for review, closed, reopened, and merged events. You can add a PR comment. "N inline comments" on a review opens those comments in Files.
- The PR number, title, state, `head → base` branch, lines added and removed, changed files, author, and a link to GitHub.
- One summary line at the top: the first merge blocker with "+N more", "Ready to merge", the merge queue state, or "Auto-merge on".
- Merge blockers, most important first, when there are 2 or more: conflicts, failed checks, changes requested, branch out of date, review required, unresolved threads, running checks, draft, blocked.
- Reviewers with their state, "(team)" for teams, and a "code owner" label. An open review request shows as pending, also after an earlier review.
- Every check on the head commit, one entry per check name, grouped by status. Passed and skipped checks share one collapsed line. Required checks have a "required" label.
- Failed and cancelled checks show why: a reason and up to 5 failure annotations.
- A banner above the composer shows Draft, Open, Closed, or the merged outcome, independently of blockers or available actions. Draft stays beside failed checks or conflicts. Queue state and position match the PR tab. Only an eligible Open PR has a merge or enqueue button. Clicking status opens the PR tab without a write.
- "Update branch" when the branch is behind its base. It merges the base in at once. "Update with rebase…" asks first, and is off while the thread's worktree has unpushed commits. After an update, a note says to pull before the next push.
- "Enable auto-merge (method)" when only running checks or a missing review block the merge. When auto-merge is on, the summary line says so, with "Disable".
- Updates by itself every 60 seconds while the PR is open. It asks bb for the thread's PR at most once per minute, and less often for no PR, closed, or merged PRs. On a GitHub rate limit, it stops background updates until the reset time and keeps the last data. A refresh button updates it at once. The tab always shows "Updated <age>".
- Shows the last known PR at once when you return to a thread or restart bb, then updates it in the background.
- Errors show as "gh not installed", "gh not logged in", or "rate limited", with a retry button. Both the PR tab and composer show initial loading, read failures, and Retry. A failed refresh keeps visibly stale last-good data with its time. Confirmed no-PR hides normal banner status.

- The **Files** sub-tab of the PR tab shows the diff of each changed file at the PR head. Files without a patch show "Diff not available". Review threads show below their line, with all comments. Outdated threads show in an "Outdated" section at the top. Resolved threads show collapsed with "Show resolved". The top shows "N open" and "N outdated". A draft reply from the agent fills the thread's reply box as "Draft from agent". The user can edit it, post it, post and resolve it, or discard it.
- In the Files sub-tab of the PR tab, "Viewed" in a file header marks the file and collapses it. The top shows "N/M viewed". Marks are kept per PR in bb (RPC `updateViewed`, kv key `viewed:v1:<owner>/<repo>#<n>`), never on GitHub. A push that changes the file's patch drops its mark.
- In the Files sub-tab of the PR tab, the "+" in the diff gutter adds a pending comment on a line. Pending comments from the user and the agent stay after a restart and go to GitHub as one review on "Submit review". Empty pending comments are not sent.
- `bb github-insight review list` and `review draft` let the thread's agent read the open review threads and save draft replies. Drafts are never posted to GitHub by the agent.

- A **Pull Requests** nav panel with three layers of open, non-draft review requests: Direct (requested from you by name), Teammates (requested from one of your teams and written by a member of the team you pick), and Team (requested from one of your teams and written by anyone else). Below them, collapsed: Reviewed (PRs you marked reviewed, and tracked PRs no layer lists any more), Merged (merged or closed PRs with a review thread, until you archive it, or with a mark, for 7 days), and Ignored. A repo can be hidden from one layer or from all of them, and shown again from the layer's "N hidden" menu. A PR labelled "DO NOT REVIEW" stays in its layer, dimmed, and is not counted. PRs are grouped by repo, PRs whose thread needs you come first, and the rest go oldest first. Each PR is one row with the CI state, number, title, labels, lines added and removed, the author's avatar, and age. Its "…" menu holds Mark reviewed, Ignore, and Archive thread. A click on the row opens the PR overview in a side panel next to the list. Empty layers and sections are left out.
- "Start review" opens the new-thread composer with the matching bb project, a new worktree, and a review prompt. The agent checks out the PR and reviews it, but does not post to GitHub. Choices that other threads can share, like the project checkout, show "Review threads need a new worktree". When a thread already shows the PR, the card shows the thread status button, which opens the thread.
- "Auto-review", in the plugin settings and off by default, starts a review thread on its own for each Direct and Teammates PR that has no thread, mark, skip label, or ignore yet, oldest first, with at most 3 working at once (1 to 6). Your own review threads count; one that waits for you does not. Each PR starts once, also when you archive its thread. A PR waiting for a slot shows "Queued" in place of "Start review".
- "Re-review" takes the place of "Ready" when you marked a PR reviewed, its review thread is idle, and the author pushed, someone commented, or your review was requested again. It sends a follow-up to the same review thread: pull the latest commits, diff them against the commit you reviewed, judge whether each of your earlier comments is resolved by the code and the replies, draft replies and new findings, and save a summary that lists only what still needs work, with no verdict line. It never posts to GitHub. The "Re-review prompt" section of the plugin settings edits everything after the Steps of that prompt (How to review, Summary rules, and Rules), next to "Review prompt" for Start review. The Steps, with the draft commands, stay fixed. After a re-review, the button comes back only after another push or new activity. "Open thread" moves to the row's "…" menu while the button shows.
- The lists refresh in the background every 5 minutes, also while the panel is closed. The panel opens at once with the last result, also after a bb restart, and shows when it was updated. Refresh updates it at once.
- "Mark reviewed" keeps a PR in "Reviewed" until its author pushes a new commit, someone else comments or replies, or your review is requested again. Then it goes back to its layer, when a layer still lists it, as "New commits", "New comments", or "Review requested again". Otherwise it stays in Reviewed with that label. Bots and approvals with no text do not count. New review comments glow in the Files sub-tab. A comment you read for 1.5 s counts as seen. It keeps its glow until you leave the tab. When you have seen all of them, "New comments" goes away. Submitting a review from the Files sub-tab marks the PR reviewed too.
- The Pull Requests sidebar row shows the number of PRs in the layers. Reviewed, Merged, Ignored, and "DO NOT REVIEW" PRs do not count. The count becomes a pill when a new PR comes in, until you open the panel. A dot shows when a review agent came back (finished, failed, or waiting for you) and you have not opened its thread yet. Its card shows "Ready", "Needs you", or "Failed" and moves to the top.
- Review threads are hidden from the sidebar thread list. The card of the PR shows the thread status button and "Archive thread", also after the PR has left the review requests. Without the plugin, `bb thread list --include-hidden` finds them.

- **Command palette** commands: "GitHub: Merge PR", "Open PR tab", "Open PR files", "Submit review", "Refresh PR", and "Open PR on GitHub". They show only for a thread with a PR, and "Merge PR" only when the PR can merge or enqueue. Merge uses loaded PR data and opens confirmation immediately, or waits for a load already in progress. It shows progress and errors in chat without changing the side panel. The PR tab and chat share merge progress and prevent duplicate writes. Other commands keep their existing tab behavior.

The plugin uses the `gh` CLI login of the host that runs the thread. The Pull Requests panel uses the `gh` login of bb's primary host. It needs no token of its own.

- An **Activity** tab in the Pull Requests panel lists comments, replies, and mentions that need you on your PRs and on the PRs you take part in, also when you hid the repo from your review lists. A click opens the PR in the side panel at that comment, where you can read the conversation and the diff and reply. Read state syncs with GitHub notifications.
- The side panel of the Pull Requests panel is the full PR tab, Overview and Files, for any PR, also one without a bb thread.
